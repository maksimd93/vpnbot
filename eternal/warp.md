# Eternal через WARP

01.11.2026 добавлен отдельный профиль LxBox:

`телефон → WARP WireGuard с маскировкой → VLESS XHTTP на Eternal → интернет`.

Это клиентская цепочка: новый IP, отдельное приложение WARP и изменения
серверного транспорта не требуются. Трафик идёт мимо Tailscale Funnel.
Прямое соединение с исходным IP Eternal по-прежнему недоступно из проверенной
домашней сети. Этот профиль даёт альтернативный маршрут, а не снимает причину
недоступности IP. Доступ с LTE нужно подтвердить на телефоне.

## Импорт

В боте: VLESS → нужный пользователь → **Ускоренный WARP**. Скопировать целиком
блок JSON, в актуальном LxBox импортировать из буфера обмена, выбрать
**Eternal · WARP** и переподключиться. JSON содержит `endpoints` WireGuard и
`outbounds` VLESS с `detour`; парсер LxBox сохраняет их как связанную цепочку.

Регистрация WARP отдельная, ключ рассчитан на одно устройство. Не запускать
этот же ключ одновременно на ПК и телефоне: WireGuard меняет адрес peer по
последним пакетам. Для второго устройства нужна отдельная регистрация и профиль.

## Конфигурация

Секретный `config/pac.json` содержит `eternal_warp`:

- `enabled`: включение выдачи;
- `uuid`: UUID существующего пользователя Xray;
- `profile`: полный приватный JSON для импорта, включая ключ WARP.

Секреты не коммитить. Бот показывает профиль только при совпадении UUID
пользователя, профиля и конфигурации; после отключения/смены UUID или смены
XHTTP-пути старый импорт скрывается. Telegram-пользователи проходят прежнюю
администраторскую проверку. Бот не отправляет новый профиль сам: выдача только
при нажатии кнопки пользователем. Дополнительного публичного сервера профилей нет.

Проверенный вход WARP: `188.114.97.1:500/UDP`, MTU 1280, keepalive 25 секунд,
IPv4 и user-space WireGuard. Маскировка LxBox: `jc=4`, `jmin=40`, `jmax=70`,
`h1=1`, `h2=2`, `h3=3`, `h4=4`, `ip=quic`, `id=www.google.com`, `ib=chrome`.
Заголовки WireGuard остаются стандартными, добавляются предварительные пакеты.
В этой проверенной конфигурации поле `reserved` не задаётся.

Второй участок: существующий VLESS XHTTP `packet-up` на TCP 443, TLS с проверкой
сертификата Eternal, ALPN h2. Windows-привязки к интерфейсу в мобильный импорт
не включены. UUID и серверные пароли не менялись.

## Проверка и пределы результата

Клиент: официальный sing-box-lx 1.14.4-lx.25, физический домашний Wi-Fi,
с явной привязкой к его интерфейсу и адресу. Работающий сторонний VPN ПК
не используется в проверяемой цепочке. Конечный IP в успешных тестах — Eternal.

- Первый вход `188.114.96.1:500`: VLESS скачал 50 МБ за 7,14 с (~56 Мбит/с),
  но повтор был ~13 Мбит/с, а ещё одна новая сессия не установилась за 10 с.
  На ПК одновременно другая сборка Gradle занимала почти весь процессор.
  Нельзя приписывать все колебания только CPU.
- Вход `188.114.97.1:500`: 50 МБ за 7,96 с (~50 Мбит/с), затем 3/3 HTTPS-запроса.
  Новая сессия: 50 МБ за 7,64 с (~52 Мбит/с), 6/6 HTTPS-запросов.
  После 35 секунд простоя следующий запрос прошёл за 0,45 с.
  Эти два прогона выполнялись с AboveNormal только у тестового ядра;
  настройки других процессов не менялись.
  Отдельная холодная сессия без предварительного WARP-запроса тоже успешна:
  IP Eternal, 10 МБ за 2,19 с (~37 Мбит/с).
- Hysteria через первый вход WARP тоже работает: 50 МБ за 11,73 с (~34 Мбит/с).
  Фиксированные 100/30 Мбит/с в клиенте не помогли: ~20 Мбит/с в повторе.
- Прямой контроль без VPN на этом ПК: ~90 Мбит/с во время загруженного CPU.
  Это не сравнение с заявленными пользователем 500 Мбит/с на телефоне.

Это измерения, а не гарантированная скорость сервиса. Маскировка и доступность
конкретного входа WARP зависят от сети и могут измениться. Работающий резерв
Funnel 443 остаётся доступен.

Проверка кода: PHP lint и `eternal/test-funnel.php`, включая сохранение полной
цепочки, HTML-кодирование, маршрут кнопки, границы сообщения и отсутствие
выдачи ключа другому/отключённому пользователю.

## Откат

Установить только `eternal_warp.enabled=false` в `config/pac.json` и выбрать
прежний резерв 443 в LxBox. Импортированный ключ при этом не отзывается;
для полного отзыва удалить регистрацию WARP через её API-токен из приватного
локального файла. Не менять Funnel, серверные VPN-контейнеры и другие PAC-поля.
